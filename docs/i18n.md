# Languages

English is the default. Settings → Language switches between English and Spanish.
The `locale` cookie persists the choice for one year. The root loader reads it
before rendering, so the document's `lang` attribute and React's initial render
use the same language. Unsupported or malformed preferences fall back to English;
the browser's language does not override the default.

Translations live in `app/locales/en.json` and `app/locales/es.json`. Use
`const { t, locale } = useI18n()` in components and hooks. Add the same key to both
catalogs, then render `t("key")`. English phrases serve as keys for most messages;
related or pluralized messages use namespaced keys. Keep sentences together and
pass variable text as values, for example `t("Edit {title}", { title })`.

For counts, define `key.one` and `key.other`, then call `t("key", { count })`.
Plural selection uses `Intl.PluralRules`; dates, numbers, and currencies should
use the active `locale` with the native Intl APIs. Unknown message keys fall back
to the supplied default message or the key. The existing `defineMessages`,
`useIntl`, and `FormattedMessage` descriptor APIs are also supported.

The client translates known app-owned Spanish server errors at the display
boundary. Agent responses, user messages, saved content, and external error text
remain as supplied. Server code can use `createTranslator(localeFromCookies(...))`
when it has the request. Never keep a user's language in shared server state.

Run `npm run test:i18n` for catalog, interpolation, pluralization, and preference
checks. After `npm run build`, run `npm run test:chat:browser` with
`CHAT_TEST_BROWSER` set to a Chromium browser executable to verify server rendering,
switching, navigation, reload persistence, and the existing chat flows.
